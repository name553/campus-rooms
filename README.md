# Campus Rooms

Сервис позволяет просматривать аудитории, создавать и отменять бронирования,
а также находить бронирования по аудитории и дате. Предназначен для учёта
занятости учебных аудиторий по заявкам, добавленным во время работы приложения.

## Возможности

- `GET /rooms` — список аудиторий; параметр `min_capacity` фильтрует их по вместимости.
- `POST /bookings` — создать бронирование.
- `GET /bookings` — список бронирований; параметры `room_id` и `date` задают фильтры.
- `DELETE /bookings/{booking_id}` — отменить бронирование.
- `GET /health` — проверить работоспособность.
- `GET /version` — узнать версию и название приложения.

Доступны аудитории 101, 202 и 303 вместимостью 20, 35 и 80 человек.
Пересечение бронирований в одной аудитории в один день возвращает `409`.
Соседние интервалы, например `10:00–11:30` и `11:30–13:00`, разрешены.
Неизвестная аудитория или бронирование возвращают `404`, некорректные данные — `422`.

## Ограничения

Бронирования хранятся в памяти процесса и исчезают после остановки или перезапуска
приложения. Все клиенты одного запущенного экземпляра используют общий список;
отдельные экземпляры имеют независимые списки. Приложение запускается с одним worker.

Реальное расписание университета не загружается: занятость определяется только
по бронированиям, добавленным через API. Авторизации нет; любой клиент может
отменить бронирование.

## Установка

Нужны Python 3.12 и Git. Команды ниже предназначены для Windows PowerShell.

```powershell
git clone https://github.com/name553/campus-rooms.git
cd campus-rooms
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Настройки

- `APP_NAME` — название приложения. По умолчанию: `Бронирование аудиторий`.
- `LOG_LEVEL` — уровень логов приложения. По умолчанию: `INFO`.
  Допустимы `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`.
  Неизвестное значение заменяется на `INFO`.

Файл `.env.example` содержит пример настроек. При необходимости скопируйте
его в `.env` рядом с `app_final.py` и измените значения:

```powershell
Copy-Item .env.example .env
```

Приложение автоматически загружает `.env`; переменные окружения терминала
имеют приоритет. После изменения настроек требуется перезапуск.
Файл `.env` исключён из Git. Настройка `LOG_LEVEL` относится к логам приложения;
уровень логов Uvicorn настраивается отдельно.

## Запуск

Обычный запуск:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app_final:app --host 127.0.0.1 --port 8000
```

Для разработки с автоматическим перезапуском:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app_final:app --host 127.0.0.1 --port 8000 --reload
```

Документация и форма отправки запросов:
[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).
Для остановки сервера нажмите `Ctrl+C`.

## Пример бронирования

В `/docs` откройте `POST /bookings`, нажмите **Try it out**, замените тело запроса
на следующий JSON и нажмите **Execute**:

```json
{
  "room_id": 101,
  "date": "2026-11-10",
  "start_time": "10:00",
  "end_time": "11:30",
  "purpose": "Подготовка к экзамену"
}
```

При свободном интервале сервис вернёт `201` и бронирование с присвоенным `id`.
Повторный запрос на то же время вернёт `409`.
Время задаётся по Москве, без суффикса часового пояса. Начало и конец относятся
к одной дате; конец должен быть позже начала. Прошедшие даты допускаются.

## Проверка работоспособности

При работающем сервере выполните в другом окне PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/version
```

Ожидаемые JSON-ответы при настройках по умолчанию:

- `/health` — `{"status":"ok"}`.
- `/version` — `{"version":"1.0.0","app_name":"Бронирование аудиторий"}`.

`Invoke-RestMethod` отображает поля ответа как объект PowerShell.

## Автоматические тесты

Установите зависимости для разработки и запустите тесты:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -v
```

В активированном окружении команда запуска — `python -m pytest -v`.

Проверяются работоспособность, создание, фильтрация и отмена бронирований,
пересечения и соседние интервалы, ошибочные данные, одновременные запросы,
настройки и логи. Всего 30 тестовых случаев. Каждый тест получает пустое хранилище.

## Логи и диагностика

Логи выводятся в терминал сервера. При уровне `INFO` видны запуск и остановка,
запросы, создание и отмена бронирований, конфликты времени.

Если приложение не работает:

- `No module named ...` — установите зависимости тем же Python, которым запускаете сервер.
- Ошибка импорта `app_final` — проверьте, что терминал открыт в папке с `app_final.py`.
- `Address already in use` — остановите предыдущий сервер или выберите другой порт через `--port 8001`.
- `Connection refused` — проверьте, запущен ли сервер и верно ли указан адрес.
- `422` — подробности ошибки входных данных находятся в поле `detail`.
- `500 Internal Server Error` — посмотрите traceback в терминале сервера.
- `404` по адресу `/` — ожидаемый результат: стартовой страницы нет. Используйте `/health` или `/docs`.

## GitHub Actions

Workflow находится в `.github/workflows/ci.yml`.

При `push` и `pull_request` GitHub запускает тесты на Ubuntu с Python 3.12.
После успешных тестов создаётся artifact `classroom-booking` с ZIP-архивом
исходников, зависимостей, тестов и README. В него также входит `.env.example`;
настоящий `.env`, виртуальное окружение и история Git не включаются.

Архив доступен на странице запуска во вкладке
[Actions](https://github.com/name553/campus-rooms/actions) и хранится 14 дней.
